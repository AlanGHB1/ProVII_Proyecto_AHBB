# Debug Changelog — 20260403_100926_476703

## Root Causes Found

### Issue 1 — `DATABASE_URL` never loaded at runtime
`main.ts` had no `import 'dotenv/config'` — only the Prisma CLI config (`prisma.config.ts`) and the DB init script loaded dotenv. So `process.env.DATABASE_URL` was `undefined` when NestJS started.

### Issue 2 — Prisma v7 + custom output requires explicit constructor options
In Prisma v7, when using a custom `output` path in `schema.prisma`, the generated `PrismaClient` **must** receive `{ datasourceUrl }` at construction time. The old implicit env-reading behavior (`new PrismaClient()` reading `DATABASE_URL` automatically) no longer works for custom-output clients.

---

## Changes Made

### 1. Load dotenv before NestJS bootstrap
- **File:** `academia-backend/src/main.ts`
- **Change:** Added `import 'dotenv/config'` as the very first import, before `NestFactory`. This ensures `process.env.DATABASE_URL` is populated before any module instantiation.
- **Revert:** Remove the `import 'dotenv/config'` line.

### 2. Pass `datasourceUrl` to PrismaClient constructor
- **File:** `academia-backend/src/prisma.service.ts`
- **Change:** Added explicit `constructor()` that calls `super({ datasourceUrl: process.env.DATABASE_URL })`, satisfying the Prisma v7 requirement for custom-output clients.
- **Revert:** Remove the `constructor()` block.

---

### 3. Replaced `datasourceUrl` with `PrismaPg` driver adapter (Prisma v7 requirement)
- **File:** `academia-backend/src/prisma.service.ts`
- **Change:** Replaced `super({ datasourceUrl })` with `super({ adapter: new PrismaPg({ connectionString: process.env.DATABASE_URL! }) })`. In Prisma v7, `PrismaClientOptions` removed `datasourceUrl` — connection is now configured via a driver adapter (`@prisma/adapter-pg`).
- **Package installed:** `@prisma/adapter-pg` (added to `academia-backend/package.json`)
- **Revert:** Remove `PrismaPg` import and revert constructor (though `datasourceUrl` no longer exists in v7 types).
